# Contributing

Contributions, technical observations and focused feedback are welcome.

This repository documents the evolution of a real production website, so contributions should address specific, reproducible problems rather than broad redesign preferences.

## Useful contributions

Good issues and discussions include:

- accessibility defects with reproducible steps;
- keyboard or screen-reader interaction problems;
- responsive layout regressions;
- measurable performance opportunities;
- semantic HTML improvements;
- technical SEO observations supported by evidence;
- browser compatibility issues;
- maintainability improvements with a clear benefit.

## Please include

When reporting a problem, include where possible:

- affected URL or page type;
- browser and device or viewport;
- reproduction steps;
- expected behaviour;
- observed behaviour;
- relevant measurements;
- screenshots only when they contain no private or sensitive information.

## Evidence levels

Please distinguish between:

- `VERIFIED`: directly observed or measured;
- `HIGH-CONFIDENCE`: strongly supported but incompletely verified;
- `REQUIRES VERIFICATION`: plausible but not yet demonstrated;
- `PROPOSAL`: suggested change that has not been approved or implemented.

Do not report an unverified assumption as an established defect.

## Scope

The repository is intended for public technical documentation.

Please do not submit credentials, tokens, private configuration, database exports, personal data, private correspondence, internal commercial information, or production infrastructure details not required to reproduce the issue.

If you believe you have found a security vulnerability, do not open a public issue. Follow `SECURITY.md`.

## Design philosophy

The project is intentionally conservative.

A change should solve a verified problem or have a clear benefit. Large redesigns, additional dependencies and feature expansion are not goals by themselves.

Mobile behaviour has priority when trade-offs are necessary.
